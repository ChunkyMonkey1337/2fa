# SSH Telegram 2FA

Двухфакторная аутентификация для SSH через Telegram-бота. После того как человек прошёл первую проверку (ключ или пароль), сервер присылает администратору сообщение с IP, пользователем и временем и двумя кнопками: **✅ Принять** и **❌ Отклонить**. Пока никто не нажал «Принять», вход не завершается.

Работает на Debian и Ubuntu. Подключается к SSH через PAM (`pam_exec`), поэтому не зависит от порта SSH и способа входа.

## Как это работает

1. Клиент подключается по SSH и проходит первую проверку (ключ или пароль).
2. На этапе `account` PAM запускает `pam_script.py`.
3. Скрипт отправляет всем администраторам сообщение с кнопками.
4. Бот (`tg_bot.py`, служба `ssh-tg-auth`) получает нажатие, проверяет, что нажал администратор и подпись кнопки верна, и помечает запрос принятым или отклонённым.
5. `pam_script.py` видит решение: «Принять» впускает, «Отклонить» или тишина дольше `TIMEOUT` не впускают.

Дополнительно:
- После принятого входа повторные входы того же пользователя с того же IP проходят без запроса `CACHE_SEC` секунд (по умолчанию 60).
- Подключения с `127.0.0.1` не проверяются.
- Если Telegram недоступен, вход закрыт (`FAIL_SAFE=false`).
- После `MAX_FAILS` отклонённых или просроченных запросов с одного IP новые запросы блокируются на `BLOCK_SEC`.

## Требования

- Debian или Ubuntu, доступ root, Python 3.9+.
- В `sshd` включён `UsePAM yes` (установщик это проверяет).
- Бот от [@BotFather](https://t.me/BotFather) и числовой Telegram ID каждого администратора.
- **Консоль или rescue-режим у хостера** на случай, если вы заблокируете себя.

## Установка

1. В Telegram откройте @BotFather, выполните `/newbot` и сохраните токен.
2. Узнайте свой числовой Telegram ID (например, отправьте любое сообщение боту-определителю ID вроде @userinfobot).
3. Откройте своего нового бота и нажмите **/start**. Без этого бот не сможет вам писать.
4. На сервере выполните: `sudo bash install-2fa.sh`
   - Токен при вводе не отображается на экране, это нормально.
   - Установщик отправит тестовое сообщение и спросит, пришло ли оно.
5. **Не закрывайте текущую SSH-сессию.** Откройте новое окно, подключитесь и подтвердите вход в Telegram.

Если что-то пошло не так на этапах до PAM, установка останавливается, не меняя SSH.

## Администраторы

Администратор — это Telegram-аккаунт, чей ID указан в `ADMIN_ID`. Каждый администратор:
- получает запросы на вход;
- может принять или отклонить любой запрос;
- может отправлять команды боту, включая `/disable`.

Если администраторов несколько, запрос приходит всем. Решает тот, кто нажал первым. У остальных сообщение остаётся с кнопками, но их нажатие ответит «Сессия истекла или обработана». Запросы нельзя направить только конкретному человеку, поэтому добавляйте только тех, кому доверяете.

### Добавить администратора

1. Новый администратор узнаёт свой числовой Telegram ID.
2. Он открывает бота и нажимает **/start**.
3. На сервере:
   ```bash
   sudo nano /opt/ssh-tg-auth/.env
   ```
   Добавьте ID через запятую, без пробелов и без кавычек:
   ```
   ADMIN_ID=111111111,222222222
   ```
4. Перезапустите бота (иначе он не примет нажатия нового администратора):
   ```bash
   sudo systemctl restart ssh-tg-auth
   ```
5. Новый администратор отправляет боту `/status`. Если бот ответил, всё работает.

В `ADMIN_ID` указываются ID людей, а не групп и каналов: проверка прав идёт по ID нажавшего.

### Убрать администратора

Удалите его ID из `ADMIN_ID` в `/opt/ssh-tg-auth/.env` и выполните `sudo systemctl restart ssh-tg-auth`.

### Сменить токен бота

Отозвать старый токен можно в @BotFather (`/revoke`). Новый запишите в `BOT_TOKEN` в `.env`, затем `sudo systemctl restart ssh-tg-auth`.

## Команды бота

Команды принимаются только от администраторов.

| Команда | Что делает |
|---|---|
| `/start`, `/status` | Показывает, включена ли 2FA |
| `/disable [минуты]` | Временно отключает 2FA. По умолчанию 15 минут, максимум 60. Потом включится сама |
| `/enable` | Включает 2FA сразу |
| `/unblock` | Снимает блокировки IP после серии отклонённых или просроченных запросов |

### Меню команд в Telegram

Кнопка меню со списком команд появится у бота, если задать команды в @BotFather: `/setcommands`, выбрать бота и отправить:

```
status - состояние 2FA
disable - отключить 2FA на N минут
enable - включить 2FA
unblock - снять блокировку IP
```

## Настройки (`/opt/ssh-tg-auth/.env`)

Файл редактируется от root, права `600`.

| Параметр | По умолчанию | Назначение | Когда применяется |
|---|---|---|---|
| `BOT_TOKEN` | — | Токен бота | После перезапуска бота |
| `ADMIN_ID` | — | ID администраторов через запятую | После перезапуска бота |
| `SECRET_KEY` | случайный | Подпись кнопок. Не менять без нужды | После перезапуска бота |
| `SERVER_IP` | определяется при установке | Только для текста уведомления | Сразу |
| `FAIL_SAFE` | `false` | `false`: если Telegram недоступен, вход закрыт. `true`: пускает без подтверждения (небезопасно) | Сразу |
| `TIMEOUT` | `120` | Сколько секунд ждать нажатия | Сразу |
| `CACHE_SEC` | `60` | Сколько секунд после принятого входа повторные входы идут без запроса | Сразу |
| `MAX_FAILS` | `3` | Сколько отказов или таймаутов с одного IP до блокировки | Сразу |
| `BLOCK_SEC` | `600` | Окно подсчёта отказов и длительность блокировки, секунд | Сразу |
| `DISABLE_TTL_MIN` | `15` | Срок `/disable` без аргумента, минут | После перезапуска бота |

### Если Telegram у вас тормозит

Запрос ждёт решения внутри входа по SSH, поэтому `sshd` может оборвать соединение раньше по `LoginGraceTime` (по умолчанию 120 секунд с начала подключения). Чтобы весь `TIMEOUT` действительно работал, поднимите `LoginGraceTime` с запасом, например:

```
# /etc/ssh/sshd_config
LoginGraceTime 180
```

Затем `sudo systemctl reload ssh` и, при необходимости, `TIMEOUT=150` в `.env`.

## Логи и диагностика

```bash
sudo journalctl -t ssh-tg-auth -n 50      # события входа (решения, блокировки, ошибки отправки)
sudo journalctl -t ssh-tg-auth-bot -n 50  # действия администраторов (/disable, /enable, /unblock)
sudo journalctl -u ssh-tg-auth -n 50      # служба бота (старт, падения)
sudo systemctl status ssh-tg-auth
```

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| Сообщение с запросом не приходит | Нажали ли вы `/start` у бота; верный ли токен и ID; `journalctl -t ssh-tg-auth`; доступ сервера к `api.telegram.org` |
| SSH сразу отвечает `Permission denied` без запроса | Ваш IP заблокирован (`/unblock` в боте), Telegram недоступен при `FAIL_SAFE=false`, либо `.env` неполный. Причина будет в `journalctl -t ssh-tg-auth` |
| Нажали, а бот пишет «Сессия истекла или обработана» | Запрос уже закрыт по таймауту или его обработал другой администратор |
| Запросы приходят на каждый `scp`, `rsync`, Ansible | Каждый новый вход по SSH проверяется. Повторные входы в течение `CACHE_SEC` проходят без запроса |
| Бот не запускается | `journalctl -u ssh-tg-auth -n 50` |
| Нет доступа к Telegram, а войти нужно | Консоль хостера, затем `sudo bash uninstall-2fa.sh` |

## Безопасность: что важно знать

- Второй фактор здесь — ваш аккаунт Telegram. Включите в нём облачный пароль (двухэтапную проверку) и код-пароль на телефоне.
- 2FA срабатывает **после** первой проверки. Она не заменяет ключи SSH: отключите вход по паролю (`PasswordAuthentication no`).
- Любой администратор может командой `/disable` отключить защиту на срок до 60 минут.
- Кнопка «Принять» уязвима к «усталости»: если вы не пытались войти, нажимайте «Отклонить» и проверяйте IP в сообщении.
- Подключения с `127.0.0.1` не проверяются (локальные туннели и службы на самом сервере проходят без запроса).
- Если Telegram недоступен, вход закрыт. Всегда держите под рукой консоль хостера.
- Токен бота лежит в `/opt/ssh-tg-auth/.env` (доступ только root). Не публикуйте его и не добавляйте в репозиторий.

## Обновление и переустановка

Повторный запуск `install-2fa.sh` пересоздаёт `.env`: токен, ID и `SECRET_KEY` вводятся и генерируются заново, а ваши изменения настроек пропадают. Сначала сохраните копию:

```bash
sudo cp /opt/ssh-tg-auth/.env ~/ssh-tg-auth.env.bak
```

## Удаление

```bash
sudo bash uninstall-2fa.sh             # полное удаление (спросит про каталог /opt/ssh-tg-auth)
sudo bash uninstall-2fa.sh --keep-files  # снять защиту, файлы оставить
sudo bash uninstall-2fa.sh --yes       # без вопросов
```

После удаления отзовите токен в @BotFather (`/revoke`) или удалите бота (`/deletebot`).

Экстренный способ снять защиту, если скриптов под рукой нет:

```bash
sudo sed -i '/pam_script.py/d' /etc/pam.d/sshd
```

## Где что лежит

| Путь | Что это |
|---|---|
| `/opt/ssh-tg-auth/.env` | Настройки и токен бота |
| `/opt/ssh-tg-auth/pam_script.py` | Скрипт, который PAM запускает при входе |
| `/opt/ssh-tg-auth/tg_bot.py` | Бот |
| `/opt/ssh-tg-auth/venv/` | Окружение Python |
| `/opt/ssh-tg-auth/2fa_disabled` | Временный флаг от `/disable` (есть только пока отключено) |
| `/etc/systemd/system/ssh-tg-auth.service` | Служба бота |
| `/etc/pam.d/sshd` | Сюда добавлена строка с `pam_exec`; рядом копии `sshd.bak-*` |
| `/etc/tmpfiles.d/ssh-tg-auth.conf` | Создание рабочего каталога после перезагрузки |
| `/dev/shm/ssh_tg_auth/` | Временные данные запросов (очищается при перезагрузке) |
